## Abstract
Chirpy 테마의 글 오른쪽에 표시되는 목차(TOC)는 기본적으로 현재 읽고 있는 섹션의 하위 항목만 펼쳐 보여 준다.
글이 길고 `###`, `####` 단계의 소제목이 많으면, 스크롤하기 전에는 하위 목차가 보이지 않아 글 전체 구조를 한눈에 파악하기 어렵다.
이 글에서는 하위 목차가 항상 펼쳐져 있도록 바꾼 방법과, 왜 그렇게 동작하는지를 정리한다.

참고한 글: [Chirpy 목차(toc) 항상 열기](https://namju.kim/posts/chirpy-toc-always-open/)

## 1. 원인: tocbot 의 접기 동작
Chirpy 는 목차를 직접 만들지 않고 [tocbot](https://github.com/tscanlin/tocbot) 라이브러리로 생성한다.
이 블로그 저장소에서는 `_javascript/modules/components/toc/toc-desktop.js` 에서 tocbot 을 초기화한다.

```javascript
// _javascript/modules/components/toc/toc-desktop.js
export class TocDesktop {
  static options = {
    tocSelector: '#toc',
    contentSelector: '.content',
    ignoreSelector: '[data-toc-skip]',
    headingSelector: 'h2, h3, h4',
    orderedList: false,
    scrollSmooth: false,
    headingsOffset: 16 * 2 // 2rem
  };
  // ...
}
```

`headingSelector` 가 `h2, h3, h4` 이므로 세 단계의 제목이 목차에 들어간다.
그런데 옵션에 `collapseDepth` 가 없으므로 tocbot 기본값 `0` 이 쓰인다.
이 값이면 tocbot 은 현재 위치가 아닌 하위 목록(`orderedList: false` 이므로 `<ul>`)에 `is-collapsed` 클래스를 붙이고, 스크롤 위치가 바뀔 때마다 이 클래스를 다시 붙였다 뗐다 한다.
tocbot 기본 스타일(`tocbot.min.css`)에는 다음 규칙이 들어 있다.

```css
.is-collapsible { max-height: 1000px; overflow: hidden; transition: all 300ms ease-in-out; }
.is-collapsed   { max-height: 0; }
```

그래서 `is-collapsed` 가 붙은 목록은 높이가 0 이 되어 화면에서 사라진다.

정리하면, 하위 목차가 숨는 이유는 HTML 에 항목이 없어서가 아니라 CSS 로 높이가 0 이 되기 때문이다.

## 2. 해결: `is-collapsed` 의 높이 제한 해제
가장 간단한 방법은 `is-collapsed` 클래스가 붙어도 높이 제한이 걸리지 않도록 스타일을 덮어쓰는 것이다.
Chirpy 는 사용자 스타일을 넣는 자리로 `assets/css/jekyll-theme-chirpy.scss` 를 제공하므로, 파일 끝에 규칙을 추가한다.

```scss
// assets/css/jekyll-theme-chirpy.scss
---
---

/* prettier-ignore */
@use 'main
{%- if jekyll.environment == 'production' -%}
  .bundle
{%- endif -%}
';

/* append your custom style below */
.is-collapsed {
  max-height: none !important;
}
```

- 파일 맨 위의 빈 front matter(`---` 두 줄)는 Jekyll 이 이 파일을 Sass 로 처리하게 만드는 표시이므로 지우면 안 된다.
- `!important` 를 붙인 이유는 위의 tocbot 규칙과 선택자 우선순위가 같기 때문이다. 우선순위가 같으면 나중에 로드된 CSS 가 이기는데, `tocbot.min.css` 는 테마 CSS 와 별도 파일로 로드되므로 순서에 기대지 않고 확실히 덮어쓰도록 했다.
- `max-height: none` 은 높이 상한을 없애는 값이다. `display` 를 건드리지 않으므로 tocbot 의 현재 위치 강조(`is-active-link`)는 그대로 동작한다.

## 3. 다른 방법: `collapseDepth` 옵션
CSS 대신 tocbot 옵션으로도 같은 결과를 얻을 수 있다.
`collapseDepth` 는 "몇 단계까지 접지 않을지" 를 정하는 값이고, 제목 단계는 최대 6 이므로 `6` 을 주면 모든 단계가 펼쳐진다.

```javascript
static options = {
  tocSelector: '#toc',
  contentSelector: '.content',
  ignoreSelector: '[data-toc-skip]',
  headingSelector: 'h2, h3, h4',
  collapseDepth: 6, // 모든 단계를 펼친 상태로 유지
  orderedList: false,
  scrollSmooth: false,
  headingsOffset: 16 * 2
};
```

이 방법은 tocbot 이 처음부터 클래스를 붙이지 않으므로 의도가 더 분명하다.
다만 `_javascript` 의 소스를 고치면 `npm run build` 로 JS 번들(`assets/js/dist`)을 다시 만들어야 하고, 테마를 업데이트할 때 충돌이 날 수 있다.
CSS 한 줄은 사용자 스타일 파일에만 들어가므로 테마 업데이트 영향을 덜 받는다. 그래서 이 블로그에는 CSS 방법을 적용했다.

참고로 이 저장소의 모바일 목차(`toc-mobile.js`)는 이미 `collapseDepth: 4` 로 설정되어 있어서, 모바일 팝업에서는 원래부터 모든 단계가 펼쳐져 보인다.

## 4. 결과 확인
로컬에서 `bundle exec jekyll serve` 로 띄운 뒤, `###` 소제목이 여러 개 있는 글을 열어 확인한다.

| 상태 | 오른쪽 목차 |
| --- | --- |
| 적용 전 | 현재 읽는 `##` 섹션의 하위 항목만 보이고, 나머지 섹션은 `##` 제목만 보인다. |
| 적용 후 | 페이지를 열자마자 모든 `##`, `###`, `####` 항목이 보인다. 스크롤해도 목록이 접히지 않는다. |

개발자 도구에서 하위 `<ul>` 요소를 선택해 보면, 적용 후에도 `is-collapsed` 클래스는 그대로 붙어 있지만 계산된 `max-height` 가 `none` 으로 바뀐 것을 확인할 수 있다.
클래스 자체는 tocbot 이 계속 관리하고, 보이는 방식만 CSS 로 바꾼 것이다.
